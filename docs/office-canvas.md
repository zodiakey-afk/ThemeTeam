# 办公室画布与周边交互

本文基于用户补充草案细化预期体验、识别冲突并提出候选解法。它不是已实现功能说明，也不代表 CodingSpec G2/G3 通过。正式 HLD/LLD、机器可读契约、依赖版本与实现计划，应在需求/NFR 确认后冻结。

## 1. 定位与范围

办公室是业务运行状态的空间视图，不是第二套编排系统。任务执行、会议发言和审批以服务端为准；人物动作解释这些事实，不能通过“动画播完”判定任务完成，也不能通过走到老板门口获得权限。

近期目标：一个工作区、一个可运行团队、一层办公室，3 人默认部署，8 个初始工位、6 个会议座位。预留多团队/楼层引用但不在首个画布迭代同时实现。公司知识库、工具沙盒和桌面打包不阻塞静态场景预研，但真实工具执行必须等安全门禁。

保留《主题医院》式空间秩序和像素人物辨识度，不复用其受版权保护素材。默认固定等轴测视角，无自由旋转、透视相机或早期 3D。

### 1.1 已确认的设计基准

2026-09-08，用户明确要求办公室画布 UI、交互及设计方案参考游戏《主题医院》，并要求据此更新方案。**这是默认办公室画布的主要设计基准，不只是宽泛的“复古”“像素”或“2.5D”标签。** 后续视觉稿、资产、地图、交互原型与最终实现必须沿用同一基准；不再反复询问是否采用该参考方向。

参考的是经营模拟游戏中的连续建筑空间、对象操作、人物活动与局部反馈，不是照搬医院业务、原游戏全部键鼠操作或版权资产。招聘/任务/会议/审批仍按本应用语义设计；首期不因此增加自由建造、经营货币、饥饿值或医疗玩法。

| 编号 | 应呈现的《主题医院》式特征 | 本产品的具体约束 | 不合格的替代方式 |
|---|---|---|---|
| TH-01 | 可观察内部的等轴测建筑 | 固定 2:1 菱形地面、半高/剖切墙、门洞与连续走廊；四区域属于同一办公室 | 四张独立房间卡片、平面矩形加阴影、以背景插画替代可运行场景 |
| TH-02 | 家具定义房间用途 | 工位有桌椅/CRT，会议室有桌椅/白板，老板室有控制台，咖啡角有饮水机；家具与角色比例一致 | 只用房间标题或色块区分功能，人物与桌椅尺寸失配 |
| TH-03 | 人物是可跟踪的活动主体 | PM/Dev/QA 有稳定轮廓、配色和朝向；经门洞行走、停步、入座、工作、围桌发言 | 圆点/头像标签充当人物，直接瞬移，只有状态文字闪烁 |
| TH-04 | 操作对象后产生局部反馈 | 点人物选中/详情、点桌子开会议入口；合法目标、路径、占位/受阻均在场景反馈 | 每次点击跳离办公室，依赖与对象无关的全屏弹窗或装饰特效 |
| TH-05 | 紧凑经营工具与可读状态 | 地面选中轮廓、短气泡、电脑亮灭、克制的警示；工具/面板靠边停靠 | 大幅营销标题、卡片套卡片、满屏长聊天遮住场景、全屏闪红 |
| TH-06 | 像素资源与真实遮挡统一 | 角色/家具统一投影、像素密度、光照与脚底锚点；人物前后经过桌椅/墙体时关系正确 | 只关抗锯齿就声称像素风，所有人物永远压在所有家具上面 |

### 1.2 主题与周边模块边界

默认体验是《主题医院》式办公室配紧凑复古经营工具外壳；中文长文、表单、看板仍保持高可读性，不能为了像素字体牺牲业务操作。灰白操作面板不是把办公室改成企业后台的理由，画布内仍需有地砖、墙面、家具与人物组成的真实空间。

现代主题只改变 DOM 工具与信息面板的皮肤，不改变默认办公室的地图拓扑、人物比例、对象交互和寻路规则。极简网格是后续另选的高密度工作视图，不是默认场景的验收替代品。文件导入/长文本/审批保留 DOM 确认流程，画布承担目标识别和定位，不承担富文本编辑或安全决策。

## 2. 信息布局

| 区域 | 推荐约束 | 内容与边界 |
|---|---|---|
| 顶栏 | 高 56px，紧凑排列 | 工作区/团队、楼层、连接状态、审批计数、模型入口、主题模式 |
| 左导航 | 展开 208px、折叠 48px | 房间、Agent 目录、状态筛选；只负责导航，不重复详情 |
| 主区域 | 不加装饰卡片或内层边框 | Phaser 场景铺满可用区域；镜头工具靠边停靠 |
| 右抽屉 | 320-400px，默认 360px | 单一上下文容器：Agent、任务、会议、文档、审批、设置；避免层层浮窗 |
| 底部工作区 | 展开建议 240px，可收起至 40px 标签栏 | 看板、会议/私聊、事件三个视图；文档/模型可切换全宽工作视图 |

桌面宽度至少 1280px 时使用三列；1024-1279px 默认折叠左栏，右栏按需覆盖；小于 1024px 导航与详情互斥显示，画布/看板/聊天切为主视图标签。390x844 手机画像下打开抽屉时不要求画布同时保有完整可操作区域，但关闭后相机和选择必须恢复。面板出现/关闭时重新计算镜头安全区域，不能把选中人物留在抽屉下面。

正文使用易读中文无衬线，像素字体仅限短标题/数值；字号不随视口宽度缩放、字距为 0。灰白和石墨作为界面基底，以绿、蓝、红/琥珀分别标识工作、信息和风险；暖木色仅用于家具，不让整个操作台变成棕黄色。状态同时具有图标和文本，不能只靠颜色。

工具按钮使用 lucide 图标、名称 tooltip 与可访问名称；主题/模式用分段控件、二元设置用开关、缩放用数值/步进工具。正文不展示“Phase 已完成”“这里支持拖拽”等产品说明，空态仅表达真实状态与可执行动作。

## 3. 空间与地图

候选资产基准：地砖 64x32 世界像素、角色约 32x48 世界像素，统一脚底 pivot。逻辑地图建议 32x24 格，最终尺寸以资产 PoC 和可达性验证为准，不能把旧 SVG 的像素坐标直接当格子坐标。

| 地图区域 | 位置及资产 | 交互锚点 | 联动 |
|---|---|---|---|
| 老板办公室 | 画面左上；桌椅、控制台、局部红地毯 | 门外等候点、审批控制台 | 点击进入审批/团队概览，不让 Leader 默认等同老板 |
| 开放工位 | 中央；两组四工位、CRT、隔断 | 每座 approach/stand/sit/facing | 招聘落位、选中人物、任务指派、个人文件导入 |
| 会议室 | 画面右上；长桌、6 椅、白板 | 入口、等候、六座、白板发言点 | 召集、成员选择、当前会议聊天、纪要 |
| 咖啡角 | 下方边缘；咖啡机、饮水机 | 饮水与短暂停留点 | 空闲动作，不启动模型调用或假造社交消息 |
| 档案柜 | 主走廊旁的小型功能物件 | 导入落点 | 团队文档中心入口；公司知识导入必须另行明确选择 |
| 扩容通道 | 地图边缘/楼梯 | 锁定边界、未来传送锚点 | 只显示容量建议；未解锁区域不得寻路进入 |

位置指投影后的构图方向，不是把 col/row 直接当左/上。连续走廊建议至少两格宽，门洞和工位后通道不能被家具 footprint 堵死；房间容量由合法锚点数计算，不根据视觉面积猜测。首版只允许预设座位间换位，不允许自由装修、任意拖墙或拖人物穿门改变编排状态。

Tiled 候选层约定：`ground`、`collision`、`doors`、`rooms`、`props_back`、`props_front`、`anchors`、`spawn_points`。对象保存稳定 ID、roomId、footprint、交互类型、朝向和遮挡策略；地图版本独立于资产版本。检查重复 ID、越界、跨层引用、出生点到所有合法锚点连通性以及与解锁条件的关系。

## 4. 业务状态与视觉状态

建议拆为 `activityState`、`motionState`、`pose` 和覆盖标记；具体字段进入 G2 再定契约。

| 服务端事实 | 视觉表现 | 气泡/屏幕 | 操作 |
|---|---|---|---|
| Idle | 坐姿伸展或短程去咖啡角 | 不展示伪造聊天；电脑暗屏 | 可指派、私聊、邀请 |
| Working | 在工位打字 | 简短任务名；真实运行阶段，不伪造百分比 | 查看执行、请求取消 |
| Thinking | 托腮/驻足 | 思考图标；无进度来源时只显示不定进度 | 查看可公开状态，不暴露内部推理 |
| InMeeting | 已到达者围桌/落座 | 当前公开发言摘要；完整消息进 DOM | 聊天、停止会议、看关联 |
| Blocked | 稳定警示姿态；可选短程到等候点 | 原因类别；只有 approvalId 存在才显示需审批 | 跳到确切审批/阻塞项 |
| Offline/Paused | 降低饱和度、静止 | 离线/暂停标识 | 恢复或看历史；禁用不适用命令 |
| Moving（仅 motionState） | 四向 Walking、起步/停步/入座 | “前往会议室”等短目的地 | 点击仍开详情；不自动取消现有行程 |
| Talking（覆盖层） | 说话者挥手/转向，听众轻动作 | 最近一条公开文本，节流显示 | 点气泡定位消息 |

`Standing` / `Sitting` 是姿态；`Walking` 不是任务执行状态。允许“工作任务暂停，人物正在入场，审批标记仍可见”这样的组合，但必须明确唯一主任务/主会议关联。动作优先级建议：明确停用 > 阻塞提示 > 用户确认的移动/会议 > 任务动作 > 空闲装饰。取消动画不是取消任务；取消任务必须得到服务端确认。

同一 Agent 的 appearancePreset/skin/animationPack 在刷新、换房间和模型切换后保持稳定。缺动作帧时回退到静止人物与状态标记，不让人物消失。创建面板显示四向行走与工作预览，名称、配色/头部轮廓确保远景可辨。

## 5. 手势、命中与相机

| 输入 | 行为 | 冲突与失败规则 |
|---|---|---|
| 单击人物 | 设置选择、右侧开详情，必要时安全区内轻推镜头 | 不默认猛烈拉近，不打断行走；同一对象重复点击不重置表单 |
| 悬停人物 | 延迟约 250ms 显示姓名、岗位、模型、任务/用量 HUD | 无真实用量显示“暂无数据”；拖拽时隐藏；离开/滚动即关闭 |
| 单击房间/家具热点 | 选择房间/对应业务入口 | 命中优先级：DOM 控件 > 人物 > 交互锚点 > 家具/房间 > 地面 |
| 空白单击 | 清除画布选择 | 保持相机位置；返回总览是独立命令，避免误点跳镜头 |
| 中键或空格+主键拖拽 | 平移相机 | 不发后端移动命令；按下到移动超过 6 CSS px 才识别拖拽 |
| 右键轻点人物 | 上下文菜单 | 右键移动超过阈值转平移，松开不再弹菜单；只在画布接管原生菜单 |
| 滚轮/捏合 | 以指针/手势中心缩放 0.5x-2x | 焦点在画布才消费滚轮；面板仍正常滚动 |
| 团队/Agent 导航 | 同步筛选、选择、房间/人物相机聚焦 | 手动平移退出跟随；团队切换保留各团队镜头，清理过期 hover |
| 双击会议室 | 快捷打开当前会议或召集面板 | 单击入口已可达，不能要求用户知道双击 |
| Esc | 关闭菜单/取消未提交拖拽/退出跟随 | 不取消已提交任务、会议或上传作业 |

右键菜单分组：查看/跟随、派任务/邀请会议/换座、任免 Leader/停用。危险组不能通过鼠标松开立即执行；需要明确确认、权限检查和占用说明。默认提供“停用”而非不可逆“解雇删除”；历史任务与纪要保留身份引用。

触控使用单指空白平移、双指缩放、点击对象及可见更多菜单；键盘可通过 DOM Agent 目录、房间导航、任务指派表单完成相同操作。画布失焦时不拦截系统快捷键。

气泡优先级：阻塞/审批 > 选中人物 > 当前发言者 > 常规状态。同屏默认最多 5 个详细气泡；未选中成员降为图标，镜头远景隐藏长姓名但目录保留。HUD/菜单限制在画布安全区，避开抽屉和底部工作区，中文长词/长 ID 强制换行，不能遮住人物脚下命中区域。跟随与相机 Tween 在减弱动画模式下使用即时聚焦。

## 6. 跨模块闭环

### 6.1 选择与导航

选择是客户端状态：`selectedEntity(kind,id)`、`activeTeamId`、`activeLevelId`、`panelMode`、`cameraBookmark`、`filters`。不同浏览器页签不应互相抢选中对象。服务端只保存确有业务意义的工作区配置；旧 `/api/select` 经迁移后不再承担相机/选择同步。

任务详情点击负责人 -> 定位人物；人物详情点击任务 -> 切换看板并选中卡片；会议头像 -> 定位发言者；文档来源 -> 打开原任务/会议；事件点击 -> 打开关联实体。跨实体跳转保留“返回上一上下文”和原相机，目标删除时给出历史占位，不落到无关对象。

### 6.2 任务指派

1. 从底部看板拖任务到人物/工位，按下未达阈值仍作为选择。
2. 展示目标姓名及允许/不允许的投放预览；空工位不能充当执行者。
3. 松开后确认新增/替换负责人，提示忙碌成员将排队，不自动中止其执行或会议。
4. 提交带幂等键与预期版本的业务命令；校验团队、任务、成员、权限和运行互斥。
5. 收到确认事件后同时更新卡片、人物详情与可视动作。失败恢复卡片，保留上下文并显示可重试原因。

首版交付同等可用的“指派给”表单，再加拖拽。任务在看板换列与真实执行结果有约束：不能拖到 Done 就伪造运行成功，人工结项要标记来源并保留运行结果。

### 6.3 会议

会议桌热点/人物菜单 -> 会议面板：议题、2-6 个参会者、Moderator、文档引用、轮次上限（建议默认 3）和超时（建议默认 10 分钟）。同一房间只允许一场占用会议；同一成员不可同时执行两场会议。

候选状态：Draft -> Gathering -> Active -> Summarizing -> Closed；另有 Cancelled/Failed。Gathering 先校验并保留会议座位，记录成员先前任务与固定工位，再发移动目标。运行中的任务默认需确认“安全暂停并入会”或排队，不能静默抢占。

服务端决定逻辑入会与开始时间；客户端按确认的移动意图播放，不等某浏览器上报“动画完成”才能运行会议。可设置 Gather 超时（建议 5 秒）并记录未就绪成员；浏览器后台、刷新或减弱动画不会挂死会议。有外部真实空间资源依赖时另行建业务就绪信号，不能复用渲染回调。

会议对话停靠底部聊天视图，可展开为全宽；不再叠加一块遮满地图的悬浮聊天窗。画布只显示当前发言者短摘要，白板仅展示显式发布的结构化产物，不从 token 猜造图表。

结束后以一次幂等事务关闭会议、保存消息/摘要、生成纪要及待确认任务建议，并补齐双向关联。记忆为候选，不自动已审批；总结失败显示 Failed/可重试，不伪造纪要。离场释放临时座位，人物回固定工位或下一确认目标，不恢复已取消的任务。

### 6.4 文件投放与知识作用域

| 投放点 | 默认目标 | 提交前显示 |
|---|---|---|
| 人物或已分配工位 | 该 Agent 私有资料候选 | 文件名、目标姓名、agentId、所属团队、可见范围 |
| 会议桌 | 该会议所属团队/项目资料，可关联会议 | teamId/projectId、会议标题；不是当前下拉框随时变化的值 |
| 档案柜/文档中心 | 当前明确选定团队 | 分类、范围、关联任务/会议 |
| 老板房间/空白/未知目标 | 不自动导入 | 打开目标选择；公司级必须显式确认 |

首版导入建议 `.md/.txt/.pdf`，每文件 10 MiB、单批最多 5 个；最终阈值待确认。提交时固化目标 ID，导入过程中切团队不改变已提交归属。同名文件询问新版本/独立文档；同内容重试按 hash 与幂等键去重。

作业状态：Uploaded -> Parsing -> Indexed，另有 Rejected/Failed/Cancelled。上传成功不代表已经可检索；预览区显示解析中/失败，允许重试和删除候选。扫描版 PDF 无 OCR 时明确提示不支持文本提取，不返回虚构正文。文档归档可以先完成，向量索引属于后续能力，不提前标记 Indexed。

文件名由服务端生成存储键；检查扩展名、MIME/签名、长度、页数/解析资源上限，拒绝路径穿越、可执行文件及压缩包。PDF 在受限 worker 解析；原始文件/提取内容不作为 HTML 执行。文档内容不得改变系统权限或工具策略；发送云模型/嵌入服务前明确数据去向并保留本地模式。公司/团队/个人隔离必须在每次服务端读取和检索验证，不能只靠 UI 筛选。

### 6.5 审批、模型与扩容

- 只有真实待审批项触发老板控制台徽标；点击人物警告打开对应审批，显示请求动作、理由、资源、影响、发起者与过期状态。允许/拒绝先在服务端生效再恢复任务，重复点击不重复执行工具。
- 人物详情模型名跳转全局模型配置，编辑草稿不会改变正在运行的模型。默认新配置对下次运行生效，当前运行固定 modelProfileRevision；用量来自调用记录，未知显示空态，不以动画时长估算 token。
- 工位不足 -> 展示容量建议 -> 预览可解锁区域和新增座位 -> 明确确认 -> 服务端变更地图版本/座位集合 -> 客户端重载导航与合法锚点。首版不自动购地/解锁，不自动移走现有成员。

## 7. 对技术草案的修正与候选实现

### 7.1 渲染引擎与资产

优先评估 Phaser + React/TypeScript + Zustand，而不是同时保留 React/Vue、Zustand/Redux、Phaser/Pixi 多组选项。当前并无框架依赖；选择需要通过最小资产场景、构建离线性、性能与许可证检查后冻结。

Phaser 提供渲染、输入、Camera、Sprite 和 Tween 能力；**不能认为内置了完整 A* 与多人物避让**。Tiled 的 isometric 支持也不意味着其所有对象层/瓦片偏移可直接零适配加载，应针对锁定版本做兼容测试。A* 使用成熟库，草案的 pathfinding.js 为候选，需核实维护、许可证和浏览器构建兼容；不自行手写核心 A*。

资源入口候选：[Itch.io](https://itch.io/game-assets) 与 [OpenGameArt](https://opengameart.org/)，搜索 `Isometric Office Pixel Art`。本次未下载或确定可用包。免费不等于可商用/可再分发；必须记录作者、来源、许可证版本、署名、修改与再分发条件、校验值。禁止挪用原游戏图像、音效或未知授权素材。

资产交付建议：`office_tileset.png`、`agent_spritesheet.png`、atlas JSON、`office_map.json`、animation manifest、license manifest 与缺失纹理占位。地图、角色角度/像素密度/光照必须一致；本地打包，不依赖运行时 CDN。角色部件化、idle 随机动作在基础四向帧稳定之后加入。

Nearest Neighbor + 关闭纹理平滑；缩放落在 0.5/0.75/1/1.5/2 等停靠级别，过渡过程允许亚像素相机运动，停止后按屏幕像素对齐。0.5x 缩小会丢细节，不能承诺任意缩放都“完全像素完美”；用近景停靠、DPR 限制和验收截图控制效果。

### 7.2 坐标与命中

标准 2:1 菱形投影是对平面旋转的等轴测风格近似，不应把“45 度”解释成可任意调整的相机倾角。固定 tileWidth=W、tileHeight=H、地图世界原点 `(ox, oy)`：

```text
worldX = ox + (col - row) * W / 2
worldY = oy + (col + row) * H / 2

col = ((worldX - ox) / (W / 2) + (worldY - oy) / (H / 2)) / 2
row = ((worldY - oy) / (H / 2) - (worldX - ox) / (W / 2)) / 2
```

指针先减去画布 DOM 偏移并换算逻辑 viewport，再通过 Camera 的逆变换得到世界坐标；不能拿 pageX/pageY 直接代入。Tiled origin、tile offset 和角色脚底 pivot 由适配层统一。连续 col/row 用于移动；点击格子根据地图边界约定取整并二次菱形命中判定，负坐标和边界格必须测。

DOM 气泡的映射方向相反：角色世界锚点 -> Camera 投影 -> 画布 CSS 矩形 -> 屏幕定位。ResizeObserver、DPR、缩放、相机平移都要更新；不要把后端坐标当 CSS px。

### 7.3 深度与遮挡

`col + row` 只适用于同一地面上简单对象的排序近似，**不产生近大远小，也不能单独解决高墙、多格桌子和前后景交错**。候选渲染规则：地板独立底层；可遮挡世界实体按脚底 groundY 与稳定 ID 排序；长墙/家具拆前后片或按 footprint 分段；状态 HUD 在 DOM 顶层。

不要简单把“所有家具层在人物下面”或“选中人物深度提到全局最上面”。选中人物被墙挡时淡化相关前景墙/显示轮廓，保持物理遮挡关系。仅更新发生移动/布局变化的动态对象深度，静态层预处理，不每帧全地图重排。

### 7.4 路径、占用与重规划

静态可走矩阵来自碰撞 footprint、门洞、楼层与解锁状态；四邻接网格使用匹配的 Manhattan 启发式，屏幕呈四个斜向行走方向。座椅/桌面格不可直接当路径终点，先到 approach anchor 再播放入座。

服务端验证目标与容量、预留目的地；客户端针对同一 mapVersion 计算表现路径。服务端不必接收每帧位置。动态避让先用确定性锚点预留、窄门排队和有限重规划，明确 A* 本身不解决多人对撞。阻塞 2 秒可尝试重规划，最多 2 次；仍失败保持最近合法点并显示路径受阻，不能静默穿墙/瞬移到目标。

每个移动意图携带 motionId；新确认命令使旧 Tween/旧路径失效。取消先停止在合法位置再根据业务结果转态，移除人物时释放路径/监听/座位。地图切换、浏览器休眠或断线恢复用权威快照重建合法位置，允许明确的“恢复定位”直接落点，但不模拟已经完成了业务动作。

## 8. 双层 UI 与事件约束

```text
React DOM: 导航 / 详情 / 看板 / 聊天 / 文档 / 模型 / 审批
       | selection + commands          ^ state selectors
       v                               |
Client Store + API/Event adapter (单一订阅入口)
       | scene projections             ^ interaction intents
       v                               |
Phaser: tilemap / sprite / camera / path / local motion
       （无密钥、无直接模型调用、无领域状态最终决定权）

HTTP commands -> FastAPI -> domain service -> SQLite/outbox
                                        -> worker/LangGraph
WS events <- event router <- committed events
Optional SSE <- scoped text stream（后续确有需要才启用）
```

第一版使用 HTTP 命令 + 单个 WebSocket 订阅，业务事件和公开文本 chunk 分类型复用；不立即同时启用 WS/SSE 两套恢复机制。SSE 留作明确单向文本场景/兼容传输的替代方案，同一逻辑流只能有一个权威传输源。

候选事件最小信息：eventId、schemaVersion、workspaceId、teamId、seq、entityVersion、type、entityId、correlationId、occurredAt、payload。文本 chunk 增加 messageId、chunkSeq、runId；只传可公开响应、状态摘要和工具结果，不传内部推理。

连接流程：取得一致快照及 snapshotSeq -> 从该 seq 之后订阅 -> 去重并依序应用；若实现先建 WS 再取快照，必须缓存重叠事件并按序合并。缺口/过期游标重新取快照，不能只丢弃乱序消息。断线保留只读最后视图和陈旧标记，禁用新写命令；进行中的命令重连后按幂等键查询结果，不自动重复外部副作用。

领域提交和 outbox 事件在同一事务；事件路由异常不得造成“数据库已变、客户端永远不知”。命令携带 expectedVersion/idempotencyKey；返回确认版本或稳定错误码（权限、版本冲突、容量不足、目标不可达等），不能只发自然语言事件。

Token 可批量约 50ms 刷入聊天，气泡最多约 5Hz；渲染循环只更新场景位置，不每帧写 React Store 或重建全部 DOM。消息完成后以持久化全文核对，截断气泡不丢原始消息。UI 卸载关闭订阅并销毁 Scene，避免重复监听和上下文泄漏。

## 9. 数据边界与迁移要求

| 现有对象 | 需补充的概念 | 必须保持的约束 |
|---|---|---|
| Room 的像素 x/y | Map/Layout、Level、footprint、door、anchor | roomId 稳定；投影数据与业务容量分离 |
| Agent.seatId 实为 roomId | homeSeatId、locationRoomId、targetAnchorId、motionId、activityState | 去会议不改固定工位；同一座位唯一占用 |
| Task | runId、version、合法转换、阻塞原因 | 任务、执行和人工结项可区分 |
| Meeting | participants 状态、room reservation、messages、summary job | 单次归档、双向文档/任务关联 |
| Document/Memory | scopeType + scopeOwnerId、版本/索引作业、approvalId | agent/team/company 名称不够，必须有所有者与授权 |
| ModelProfile | 密钥引用、revision、真实用量关联 | API 响应绝不暴露密钥；当前 run 配置不漂移 |
| events: string[] | 结构化事件、seq、outbox、保留策略 | 可追踪、可恢复、脱敏；不等同安全审计 |

迁移采用版本化备份 + 显式导入，不能修改并继续覆盖现有 JSON。先为每个 Agent 找到原房间，再按稳定次序分配新座位；原字段若为非工位房间，则保留当前位置并分配可用固定工位。容量不足或未知引用必须报告待修复，不能丢人/伪造座位。旧 `Walking` 无路径上下文时回最近可确认房间，以待命/待核对标识重建，不猜测原执行。

SQLite 导入前校验实体计数、引用、重复项和作用域；导入后导出核对并模拟重启。回滚回原应用及原始备份，新数据先导出保留；不宣称新版 SQLite 能直接被旧 JSON 原型读取。具体 Schema 与迁移程序在 G2 冻结，当前不改运行数据。
