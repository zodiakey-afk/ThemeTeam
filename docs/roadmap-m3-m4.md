## 1. 路线结论

- **M3：会议与协同 Beta**，对应 W11-W12，目标是把多 Agent 会议、Moderator、Leader 拆解、忙碌成员协调和成果回座做成可追踪业务闭环。
- **M4：文档与知识边界**，对应 W13-W14，目标是把文档导入、解析、预览、版本、受控检索、三层记忆候选和人工审批做成可审计闭环。
- M3/M4 依赖 M2 的 SQLite 事实源、命令幂等、事件游标、审批、artifact 隔离和 `correlationId` 追踪。
- M3/M4 不扩大到多团队 SaaS、桌面发行、离线模型或完整扩容发行；这些保留到 M5/后续版本。

## 2. M3 计划：会议与协同 Beta

### 2.1 目标

完成“选择参与者 -> 预留会议资源 -> Agent 入场 -> Moderator 控轮次 -> 流式消息 -> 摘要/任务建议 -> 释放座位并回座”的闭环。

### 2.2 工作包与里程碑

| 工作包 | 内容 | 产出 | 退出条件 |
|---|---|---|---|
| W11-A 会议领域模型 | Meeting/Conversation、参与者、Moderator、轮次、超时、取消、会议座位预留 | 版本化 API/events schema、SQLite migration、状态机 | 正常/重复/冲突/取消状态均可持久化 |
| W11-B 忙碌成员协调 | Working/Running 成员入会策略：安全暂停、排队、拒绝；固定工位与会议座位分离 | 冲突策略、审批/审计事件、回座 intent | 无覆盖工位、无重复预留、可恢复 |
| W12-A GroupChat 执行 | Moderator 控轮次、消息 chunk、超时、断线重连、取消和失败收束 | 会议运行服务、WS 事件、消息归档 | 事件可重放、消息不重复、失败可重试 |
| W12-B Leader 拆解与成果链 | 会议摘要、待确认任务建议、文档建议；必须人工确认后创建 | summary/decision/task-suggestion schema | 纪要幂等，建议不自动越权落库 |
| W12-C 办公室联动 | 入场、发言、等待、回座动画只作为业务状态投影 | scene adapter 增量事件、移动验收 | 动画不作为业务真相，取消/刷新可恢复 |

### 2.3 M3 验收

- 会议状态机：`Draft -> Gathering -> Active -> Summarizing -> Closed`，含 `Cancelled/Failed`。
- 至少 3 个 Agent 的会议正常完成、超时、取消、缺席、重复提交和断线恢复。
- Moderator 轮次限制和摘要失败重试可审计。
- Leader 任务拆解只产生待确认建议，人工确认后才创建任务。
- 忙碌成员不会被静默抢占；固定工位在会议结束后可回座。
- M3 黑盒、回归、并发、事件重放、权限和安全测试全部有证据。

## 3. M4 计划：文档与知识边界

### 3.1 目标

完成“导入/生成文档 -> 作用域确认 -> 解析/预览 -> 版本/来源追踪 -> 受控检索 -> 候选记忆 -> 人工审批”的闭环。

### 3.2 工作包与里程碑

| 工作包 | 内容 | 产出 | 退出条件 |
|---|---|---|---|
| W13-A 安全导入 | 文件大小/格式/路径/realpath/符号链接/批量限制，scopeOwner 在提交时冻结 | import_jobs、document_versions、文件存储边界 | 越界、畸形、超限、重复导入均明确失败 |
| W13-B 解析与预览 | 解析状态、取消、失败重试、纯文本/结构化预览、原始文件 hash | parser adapter、preview API、状态事件 | 解析失败不伪装成已索引 |
| W13-C 文档关系 | 文档与任务、会议、Agent、审批关联；版本不可变、来源可追踪 | 文档中心 UI/API、关联事件 | 双向跳转和审计链完整 |
| W14-A 受控索引/检索 | SQLite 元数据 + 可替换向量索引；索引失败可重试，不阻塞原始归档 | index_jobs、search API、权限过滤 | 检索结果受作用域和权限过滤 |
| W14-B 三层记忆 | company/team-agent 三层候选记忆、去重、压缩、删除和人审 | memory_items、approval flow | 未审批敏感记忆不可生效 |
| W14-C 外发与工具安全 | MCP/嵌入服务数据去向提示、默认拒绝未授权外发、审计 | threat model、security tests、ops runbook | 越权、XSS、路径穿越、明文密钥为 0 |

### 3.3 M4 验收

- 支持 PDF/文本等首批批准格式，解析失败、取消、重试和重复导入可追踪。
- 文档作用域在提交时冻结，切换团队不会改变历史归属。
- 文档版本、来源、关联任务/会议和审批状态可双向追踪。
- 检索只返回用户有权访问的内容；索引不可用不影响原始归档。
- 记忆候选默认不直接生效；高敏感内容必须人工批准。
- 安全和隐私测试覆盖恶意文件、路径穿越、XSS、跨作用域访问和外发控制。

## 4. 依赖与关键路径

```text
M2 release evidence
       |
       +--> W11-A --> W11-B --> W12-A --> W12-B --> W12-C --> M3 Beta
       |
       +--> W13-A --> W13-B --> W13-C --> W14-A --> W14-B --> W14-C --> M4 Beta
```

- M3 关键路径：会议状态机 -> 忙碌成员协调 -> GroupChat 事件恢复 -> 摘要/任务建议。
- M4 关键路径：安全导入 -> 解析/预览 -> 文档关系 -> 检索权限 -> 记忆审批。
- M3 与 M4 可并行，但必须共享 `correlationId`、审批、审计、作用域和 artifact 契约。

## 5. 门禁与人工确认

每个阶段均重新建立独立 feature run，不沿用 M2 的门禁结论：

- M3_G1/M4_G1：需求、NFR、文件/数据保留和外发边界确认。
- M3_G2/M4_G2：会议/文档/记忆契约、威胁模型、数据迁移和 ADR 技术评审。
- M3_G3/M4_G3：WBS、风险、预算、测试矩阵和项目负责人批准。
- M3_G4/M4_G4：实现、冻结 BB、回归/影响/发散测试。
- M3_G5/M4_G5：独立对抗评审、QA 签署和安全证据。
- M3_G6/M4_G6：发布/回滚/监控/运维交接。
- M3_G7/M4_G7：修改报告和最终确认。

## 6. 初始风险

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 会议动画被误当业务真相 | 状态错乱、重复入会 | 服务端状态机和 outbox 为唯一事实源 |
| 忙碌成员被会议抢占 | 任务丢失、回座失败 | 显式暂停/排队/拒绝策略，必须审计 |
| 文档解析或索引失败 | 用户误以为成果已可检索 | 归档、解析、索引状态分离，失败可重试 |
| 作用域设计不足 | 跨团队/个人记忆泄露 | scopeOwner + 服务端权限过滤 + 负例测试 |
| 向量库或外部嵌入服务不可用 | 文档闭环被外部依赖阻断 | 原始文件和元数据先本地落盘，索引异步 |
| 范围膨胀到桌面/多团队 | M3/M4 延期且难以验收 | M5 单独立项，不混入当前 DoD |

## 7. 下一步

1. 在 M2 提交后建立 M3 feature run，先冻结 W11 黑盒测试和会议状态契约。
2. 并行建立 M4 feature run，先冻结 W13 文件导入、作用域和数据保留边界。
3. M3/M4 任何真实模型、文件解析器、向量索引或外发服务接入必须单独经过安全和依赖评审。
