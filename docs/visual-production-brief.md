# 一致性约束

所有稿件采用同一办公室与三位角色：固定 2:1 等轴测、连续菱形地面、半高墙/门洞、老板室左上、工位中央、会议室右上、咖啡角边缘。中央 8 工位、会议 6 椅。三位人物通过蓝/绿/琥珀色服装及不同头部轮廓区分 PM/Dev/QA，不用抽象圆点。家具、脚底锚点、角色比例和光照统一。

参考《主题医院》的经营模拟空间与对象操作语言，但不复制原游戏素材或医院业务；地砖/墙体浅灰绿，工具外壳灰白石墨，家具局部木色，风险红色点缀。不要棕黄色铺满、卡片房间、营销标题、漂浮装饰或将文字气泡盖住人物。

## VIS-01 总览制作输入

Use case: ui-mockup。制作一张 1440x900 的办公室管理桌面效果稿。主要画面是可运行游戏式办公室，不是插画展示卡。顶部紧凑工具条、左侧房间/人物导航、右侧选中 Dev 的详情、底部可折叠任务区；中央连续办公室清晰可见，三位人物各处于思考/走向工位/待命。墙体剖切不挡门洞。只保留必要短标签，中文正文后续由 DOM 精确排版，不把生成文字当 UI 实现。

## VIS-02 近景与动作板制作输入

Use case: stylized-concept。保持 VIS-01 同一地图与人物形象，展示工位桌椅/CRT 近景、会议桌近景和同一 Dev 的四个屏幕斜向行走朝向。另展示站立、入座、打字、托腮姿态。统一缩放/脚底定位，桌椅前后遮挡明确；动作板用于资产验收，不承诺生成图直接可当 Sprite atlas。

## VIS-03 四步分镜制作输入

Use case: ui-mockup。同一摄像机/地图/人物，四个连续画面：1 选中 Dev，脚下轮廓，详情对应；2 沿走廊绕桌经门洞行走，目标工位高亮；3 到达 approach 点再入座，固定工位不改变；4 面向 CRT 工作、电脑亮起、短 Working 状态，底部相关任务选中。分镜标签放图外，不遮挡画布；补失败小图“目标占用/路径受阻”，不通过瞬移模拟成功。

## VIS-04 小屏制作输入

Use case: ui-mockup。复用同一场景。1366x768 展示折叠左栏与右侧详情，390x844 展示画布主视图和详情展开两种状态；小屏不是把桌面等比例缩小，工具可触达，关闭详情回到同一人物与镜头。

## VIS-05 连续性与失败反馈补板

Use case: ui-mockup。八格连续分镜，上排固定 PM/Dev/QA 身份与同一六椅会议桌，显示 Dev 在会议桌旁以 `DEMO` 标识发言、离桌穿过走廊、回到原工位并显示 `WORK DEMO`。下排显示 QA 已占用目标椅、红色 `OCCUPIED` 就地反馈并保留另一绿色合法椅；关闭门洞造成 `NO PATH`，人物留在原侧不瞬移；Back/取消移除错误并恢复原选择与上下文。文字仅保留上述四个短标签，不声称真实模型执行。

## VIS-06 身份一致的会议返回分镜

Use case: ui-mockup。仅表现六步连续链，不混入失败案例：蓝衣 PM、绿衣 Dev、琥珀衣高发髻 QA 围在六椅会议桌；Dev 以 `DEMO` 发言；Dev 离桌、通过同一门洞与走廊；到达原工位 approach；入座面向同一 CRT 并显示 `WORK DEMO`。六格保持同一身份、办公室地理和相机角度，不在最后回到会议桌。

## 交付方式

VIS-01 至 VIS-04 沿用用户选择的第三方 API/CLI 路径；VIS-05/06 使用优先的 Codex built-in `image_gen`，不使用或持久化用户凭据。每个产物需要实际本地文件、图像检查与来源记录；概念图不作为可运行贴图或 M1 验收通过记录。
