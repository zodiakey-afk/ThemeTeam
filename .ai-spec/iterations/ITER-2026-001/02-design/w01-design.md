# W01 实例与测试生命周期

## 范围与风险

G1 首批已由用户确认；按计划先交付 W01 小批次。风险 M：增加跨模块工厂参数，涉及服务实例生命周期和测试资源清理，但不修改业务、锁语义、持久格式、权限、请求解析或渲染。本批不视为整个 M0/M1 完成。

## 架构与详细行为

入口 `run.py -> create_server(host, port, *, store=None)` 保持原调用兼容。工厂在实际创建服务时才构造缺省 WorkspaceStore；导入 server 模块只定义类型/常量，不加载用户数据。自定义 ThreadingHTTPServer 子类持有实例属性 store，Handler 通过 `self.server.store` 获取，不使用类级共享状态或可变模块全局变量。

调用者传入 Store 时完全使用该实例，不触发缺省 Store 构造。显式 None 判断避免把有效的 false-like 实例当成缺省。调用者故意重复传入同一 Store 仍表示共享，隔离测试必须各建独立 Store，不宣称 API 能禁止调用者主动共享。

先加载/接收 Store，再交给标准库绑定监听；加载失败尚未创建 socket，绑定失败由标准库 server 构造过程关闭自己创建的 socket。工厂不自动启动线程。测试统一管理 TempDir、服务、线程和连接：资源创建后立即注册清理，LIFO 先关连接，再 shutdown/close/join，再清理目录。线程启动失败只 close socket，不调用没有运行循环的 shutdown。使用 port=0 由 OS 分配监听端口，去掉先探测再绑定的竞态和固定 sleep。

## 契约与兼容性

机器可读契约见 `contracts/w01.json`。HTTP 路由/正常响应/JSON 模型一律不变，无新依赖。仅 Python 工厂增加 keyword-only store 参数；模块内部 STORE 删除，仓内调用方已核对仅工厂/Handler/测试使用。默认应用仍访问原 JSON，测试绝不使用该路径作输入。

## 测试选择与 NFR 映射

回归：现有九项功能测试改为临时 Store，不改变其业务断言。影响：同进程两服务的状态/文件/关闭隔离；模块导入无文件读取；无参数构造的兼容行为。发散：绑定冲突、模拟线程启动失败、断言失败时清理、重复运行、同一进程重发现测试。测试规范从已批准 B01 和外部接口推导，独立评审补充 BB 用例；内部补丁路径等归 WB，不冒充黑盒。

数据 NFR：所有测试写入临时目录，四轮后真实 JSON SHA256 不变；保护器还需捕获读用户存储行为而非只检查写入 hash。可观测性：保存命令输出、退出码、Python/OS、测试计数与 hash。无热路径变化，画布/模型性能项本包不适用，留在 M1/M2。

## ADR 与威胁边界

选择 server 实例持有 Store，拒绝修改共享模块全局变量；选择 stdlib unittest/tempfile/context manager，不引入测试框架。测试临时目录只清理自身创建资源，不能通过测试写回用户数据。文件路径/XSS/伪审批等原型问题未在 W01 修复，必须保持 W02 风险登记；不得对外宣称应用已安全。

## 数据与回滚

实施验证补充：Windows 实测标准库地址复用允许重复 bind；为满足已冻结的端口冲突契约，服务子类禁用 allow_reuse_address / allow_reuse_port。未改变接口语义，具体固定端口重启可能需等待 OS 释放；测试继续使用 port=0。这是契约实现细节，不修改 BB 期望。

无数据迁移，无用户文件写入。回滚仅恢复本批工厂/测试改动，不使用 git reset 或覆盖已有用户修改；原 JSON 无须转换。不启动或停止用户正在使用的服务器；测试服务全部随机端口和临时 Store。
